# 0.2.1 升级检查与迁移边界

后端包、`uv.lock`、前端包与锁文件、FastAPI 元信息及健康接口的项目版本统一为 `0.2.1`。模块职责重划分不新增数据库结构变更；本次合并同时包含此前队列 work 与审计产物合并的结构变化，必须按实际库形状选择升级方式。

## 当前库检查

2026-10-08 对项目配置的 `novel_analysis/public` 执行只读检查：当前 ORM 必需表、字段及同 schema 外键均齐全，`pending/running/cancelling` 分析任务为 0。没有执行生产 DDL、历史记录转换、服务重启或付费模型请求。

从项目根目录执行：

```powershell
uv run python -m scripts.migrations.check_0_2_1 --schema public
```

命令读取根目录 `.env`，事务设为只读并限制查询时间。退出码 0 表示所检查结构齐全，2 表示缺项；连接或配置失败以异常退出。测试库使用 `--database-env TEST_DATABASE`。动态 `paragraph_embeddings` 的维度仍由既有专用入口管理，检查器不验证列类型、索引、数据质量或历史身份裁决，结构检查成功不能代替这些验收。

## 按源结构处理

| 实际库结构 | 处理方式 |
|---|---|
| 已有当前全部表、字段和外键 | 运行只读检查；无需重复六表迁移 |
| 新的空库 | 使用现有 `init_db()` 初始化当前 ORM，再运行只读检查 |
| 已完成角色 work 转换，仍使用旧审计表、章产物表和独立案例状态表 | 先备份、停写、收口任务，在隔离备份库演练下面的六表合并 |
| 原始 0.2.0，仍有旧流水线/身份裁决/缺少 work 与作者字段 | 使用完整发布入口 `migrate_0_2_0_to_0_2_1`，先只读预检与隔离演练，不能跳过身份、作者与混存检查 |
| 0.1.1 或更早 | 用匹配历史发布的代码先完成其升级并核对 0.2.0 源合同；本次新增入口不会猜测更早的数据语义 |
| 新旧目标表部分混存 | 拒绝继续迁移，按备份与实际迁移记录核对；不自动猜测完成状态 |

`scripts.migrations.migrate_0_1_1_to_0_2_0` 是历史升级工具，依赖对应发布的 ORM；当前 ORM 已移除其目标流水线表。旧文档中的本地 `scripts.db.migrate_queue_agents` 不作为发布入口，其转换能力已适配当前领域贡献接口并纳入下面的版本化完整迁移。

## 原始 0.2.0 的完整发布迁移

先保存完整 PostgreSQL 备份和原发布代码，停写并收口分析任务。默认命令只读取配置库并输出 JSON 预检，不建表或改写记录：

```powershell
uv run python -m scripts.migrations.migrate_0_2_0_to_0_2_1 --schema public
```

先在隔离备份 schema 演练，替换下列占位参数：

```powershell
uv run python -m scripts.migrations.migrate_0_2_0_to_0_2_1 --database-env TEST_DATABASE --schema <隔离备份schema>
uv run python -m scripts.migrations.migrate_0_2_0_to_0_2_1 --database-env TEST_DATABASE --schema <隔离备份schema> --apply --expect-database <测试数据库名>
uv run python -m scripts.migrations.check_0_2_1 --database-env TEST_DATABASE --schema <隔离备份schema>
```

入口在一个事务中完成角色 work 转换与六表合并。执行前核对数据库名、源表字段、任务状态、归档冲突、部分目标结构、旧章与已保存 work 混存，以及身份裁决的真实来源；锁定源表后再次预检。退出码 0 表示预检通过、已迁移或当前结构无需重复转换，2 表示所报告阻塞；数据库连接与 SQL 异常会使事务回滚并以异常退出。声明了单条 SQL 60 秒、锁等待 5 秒限时；这不是完整迁移的总耗时承诺。

转换保留章产物 ID 和原始载荷，恢复原章实际正文与段落输入。源章只有一条成功标注审计时关联该真实审计，多条成功尝试无法确定生产者时使用原章产物回执 ID 标识历史生产 invocation，不按最新审计 ID 猜测关联，不补造模型请求和用量。图谱按原实体状态、关系事实与实际身份裁决重建；没有 `operation_order` 的历史事件/身份事实仍保留原内容，不伪造新操作顺序。事件主链与普通跨树因果分别保留，不把普通因果改成树父边。旧案例按原成功保存章和规范化说明登记，合并相同说明的真实作者贡献，状态为 `pending`；旧结构化目标、认领与办理结果全量归档，不猜测成新合同的交付。最新诊断与实际回合、工具调用、用量迁入当前产物和审计表，章产物与审计的原时间有记录时保留；原 cloud_analysis 没有创建时间字段，新诊断产物记录迁移时间。带时区的列显式转换为 UTC 无时区，文本时间按原记录解析。

身份端点不是人物、裁决互相冲突、作者来源不明、业务状态缺成功保存章、原输入缺失或输出字段不符合契约时，预检列出记录并拒绝转换。已完成角色 work 的中间库仍使用下面的六表工具，避免重写已有不可变贡献。已满足当前全部表、字段与外键且无旧流水线的库重复执行不会写入。

原始退出表迁入 `<源schema前35字符>_annotation_archive`，其他源表在改写前保存完整数据副本；退出表外键改接同一归档的快照，后续删除新运行数据不会级联破坏这些归档。六表阶段另生成 `_turn_outputs_archive`。数据副本不包含完整原索引、约束、序列和外部对象，必须保留发布前完整备份。迁移成功时在 `noveliq_release_migrations` 保存版本与报告。回退时停写、另存升级后的新数据，再恢复发布前完整备份与匹配代码；不提供自动逆向迁移。

动态向量表维度和外部模型产物不在此次转换范围。实际生产发布仍须先演练、核对图谱、事件树、诊断和恢复结果，再明确切换库参数执行；本次新增脚本没有执行生产迁移。

## 角色 work 中间结构的六表合并

迁移实现和测试现已使用版本化入口，不依赖被 Git 忽略的 `scripts/db` 本地脚本。默认只读：

```powershell
uv run python -m scripts.migrations.migrate_turn_outputs_merge --database-env TEST_DATABASE --schema <隔离备份schema>
```

核对源表、字段、任务状态和归档冲突，确认业务结果与用量保持一致后，在隔离备份库执行：

```powershell
uv run python -m scripts.migrations.migrate_turn_outputs_merge --database-env TEST_DATABASE --schema <隔离备份schema> --apply --expect-database <测试数据库名>
uv run python -m scripts.migrations.check_0_2_1 --database-env TEST_DATABASE --schema <隔离备份schema>
```

实际发布窗口必须先保存完整数据库备份与原发布代码，停写并确认没有 `pending/running/cancelling` 任务；再将参数明确替换成实际发布库配置和数据库名。工具不自动启动生产迁移。

修复后的命令行在预检 SQL 前开启事务，解决 SQLAlchemy 查询自动开启事务后再次 `begin()` 的冲突；同时补齐旧脚本遗漏的工具调用 `message_key` 字段及唯一索引，保持后续审计去重可用。预检拒绝缺失源表/字段、部分目标结构、活动任务与已占用归档；执行要求数据库名匹配，并拒绝不存在的 schema 回退到 `public`。

合并保留原回合 ID 与工具调用关联、用量和无回合失败；保留章产物 ID、实际输入、work 与作者身份；每个 run 的诊断只迁入最新可读结果，旧诊断全量留在归档；案例状态及贡献并入原案例。旧审计消息全量归档，不伪造历史去重键。归档也保存原 `book_cases`，以便核对其合并前内容。

全部 DDL 与数据转换处于同一事务，失败整体回滚。归档 schema 为 `<源schema前35字符>_turn_outputs_archive`，内容是数据副本，不包含完整约束、索引与序列，不能替代完整备份。回退需停止新代码和写入，另存升级后新业务数据，再恢复发布前完整备份及匹配代码；不提供自动逆向迁移。
