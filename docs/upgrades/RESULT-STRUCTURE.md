# 统一项目版本与章节全书结果

## 发布版本

项目发布版本只在 `pyproject.toml` 的 `project.version` 维护，当前为 `0.2.2`。后端通过 `src/config/project_version.py` 读取，健康接口与 OpenAPI 共用这一来源。前端包和锁文件不单独声明项目版本；`uv.lock` 中项目版本为生成信息。依赖库、协议和 UUID 的版本不属于项目发布版本。

图指标、关键词、LOWESS、LTP、主题、固定合同、章末核对和事件树不再维护独立契约版本字段或版本门禁。实际算法参数、外部库信息、来源摘要与幂等校验继续保存和检查。

## 章节与全书

- 章节身份使用真实 `chapter_id`，阅读先后使用 `chapters.sequence`。章节编号与顺序不要求连续；无正文章节仍保留目录身份。
- 每章一个结果边界，不设阶段号、版本编号、当前版本或前驱链。图快照与事件森林沿正式章节边界读取。
- `event_records` 保存诊断提交的完整事件正文、真实生产者和证据，构成每个运行独立的全书结果。独立跨章事件不自动进入某章。
- `event_declarations` 保存不可变的章级正文、参与者和证据。章级节点用自身 `declaration_id` 定位，通过来源取得真实章节；`event_id` 只表示完整事件归属。
- `event_declaration_bindings` 保存声明与完整事件的归属；声明只能归属一个完整事件，所有不同声明均保留，不限制“同事件同章只有一条”。绑定不复制或改写声明正文。
- 章级关系使用原声明端点，全书关系使用完整事件端点；全书端点不会任意替换成某一条声明。
- 保存、内存贡献、快照回滚及恢复分别处理全书正文与声明归属；程序、构造器、子代理和案例办理执行链继续保留。

全书事件树继续使用既有入口。章级详情为 `GET /api/novels/{novel_id}/event-forest/chapters/{chapter_id}/nodes/{declaration_id}`，严格核对当前章并使用该章身份投影。全书详情仍按 `event_id` 读取完整事件正文。导出包含原声明、全书事件正文、全部声明归属、生产者和原文证据。

图变化分页固定运行、请求条件及首次解析的实际章节边界，后页不会随最新章节推进而改变范围。时间线和事件树分别保留自己的交互状态，桌面布局不变。

## 案例与写入

案例只管理登记、承诺和解决状态，不关联具体事实、关系或事件等业务结果。内部保留 `promised_agent_id` 以校验权限和恢复办理状态，案例内容及工具输出不暴露承诺人。

具体事实、关系、事件写入允许携带 `caseid`；诊断案例写入沿现有办理流程核验承诺。业务结果按真实生产者保存和撤回，不保存 `source_case_id`，也不返回 `case_link` 或每案例结果清单。恢复读取正式结果与案例状态，不根据案例猜测业务结果归属。

## 初始化与数据保护

静态 ORM 固定为 32 张表，每表一个 UUID 主键。`event_revisions` 由 `event_declaration_bindings` 替代，完整正文在现有 `event_records` 中保存，不增加阶段表或案例结果关联表。

初始化在建表前只读检查已有表集、列、类型、可空性、主键、唯一约束、外键目标及检查约束。空结构可初始化；已有结构须与当前模型一致。旧阶段表、混合字段、缺失约束和跨历史 schema 外键会拒绝，拒绝后不补表、不执行 ALTER、不转换或修复旧结果。

`scripts/db/init_schema.py` 默认只读检查；显式 `--apply` 才调用正式初始化入口，其同样拒绝不兼容结构。历史迁移脚本与版本事实保持原样，只对对应发布代码负责。

本次实现不清空现用数据库，不回填、迁移或覆盖历史结果。新结果必须由修正后的正式链从原始输入生成，并用独立运行身份隔离。
